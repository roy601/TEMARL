# Decisions

Written 2026-11-25, after reading the paper and the released code, before any evaluation. A smoke test (60
steps per method, no episode finished, nothing kept) checked that the policies load; it is not a result.

| # | gap | choice | why | decided on |
|---|---|---|---|---|
| 1 | Purpose | A **reproduction** in the ACM sense of the paper's evaluation results: the authors' released policies and evaluation code, unchanged, rerun by us, compared with Tables 2 and 3. A comparison with TEMARL is a separate, later protocol (STANDARD requirement 10). | STANDARD.md Section 1 | 2026-11-25 |
| 2 | Paper version and targets | The *Reinforcement Learning Journal* 2025 version (RLJ/RLC 2025 paper 77), downloaded from the publisher. Targets are the numbers printed in Tables 2 and 3 and the quantitative text claims (Sections 4.2, 5.1). Table 1 describes the environment, not results, and is not a target. Text numbers that repeat a table cell are not separate targets. | targets come from the paper | 2026-11-25 |
| 3 | What can be attempted | The repository (commit 6fe960f) releases trained policies for **H-MARL Expert** (`h-marl-3policy/saved_policies/sub/iter_49`), **H-MARL Meta** (`.../master/iter_49` with those sub-policies) and **MARL Decentralized** (`marl-1policy/models/train_marl/iter_199`), and an evaluator that plays the **Default Red** agent (`FiniteStateRedAgent`) only. Not released: policies for MARL Centralized Critic, H-MARL Collective and H-MARL Meta with fine-tuning; the Stealthy, Aggressive and Impact red agents. Those targets are **NOT ATTEMPTED** (rebuilding a red agent or retraining a method would be our own work, not a reproduction); the authors are asked. The `h-marl-4policy` models (Section 5.4) have no printed number. | released artifacts only | 2026-11-25 |
| 4 | Software | **Python 3.10** (3.10.22 via `uv`): the released `policy_state.pkl` files contain pickled Python code objects that load only under 3.10 (under 3.11 they fail with "code() argument 13 must be str", the 3.10 to 3.11 signature change). The CAGE 4 environment at commit **8c3c50c** (CybORG's code is unchanged since 2024-04-29; later commits edit the README, so it is the code H-MARL was trained on in Oct-Nov 2024) with the same requirements as our CAGE 4 reproduction (`requirements_hmarl.txt` = `../cage4/requirements_cage4.txt`: **Ray 2.10.0**, the version the H-MARL README names; torch 2.2.0; unpinned packages as of 2024-06-15). | the policies decide the Python version | 2026-11-25 |
| 5 | Pins | Both repositories cloned at their commits with `core.autocrlf=false`; the SHA-256 of all 87 files of the evaluated policies (25 `policy_state.pkl`) and of the code that loads and scores them is in `POLICY_SHA256.txt`, checked before every run (`fetch.py`). | unchanged artifacts | 2026-11-25 |
| 6 | Evaluation code | The authors' `evaluation_metrics.run_evaluation` of each method (Expert: `h-marl-3policy/subpolicies`, Meta: `h-marl-3policy/master`, Decentralized: `marl-1policy`), called unchanged with `max_eps=100`, `write_to_file=False`, `seed=s`. Their `COMPUTE_METRICS` switch (README: "enable the COMPUTE_METRICS flag") is set to True at run time on the imported module; no file is edited. `verify` checks, per method, that their plain `evaluation.py` and `evaluation_metrics.py` give the same average reward for the same seed (the metrics do not change the game) and that a second run repeats it. | the authors' own scoring | 2026-11-25 |
| 7 | Reading the metrics | The script prints running averages. Per (method, seed): episode rewards are recovered exactly from the printed running means; the last summary gives Clean Hosts (`Noninfection frac across subnets`), Non-Escalated Hosts (`Nonprivileged frac across subnets`), Mean Time to Recover (`Mean stride across subnets`, the infection stride), Useful Recoveries (`True pos across subnets`) and Wasted Recoveries (`False pos across subnets`), each as printed (the script rounds to 2 decimals). Recovery Precision = TP / (TP + FP) and Recovery Error = FP / (TP + FP), the paper's Section 5.5 formulas, from those two values. **Red Impact Count** = per episode, the sum over red agents of their Impact counts on operational hosts (the script prints each agent's full per-episode list), averaged over the 100 episodes. The paper does not say how agents are combined; summing is our reading of "number of times the OT service is impacted", asked of the authors. | stated before results | 2026-11-25 |
| 8 | Seeds and variance | The released policies are **one** trained policy per method, so only evaluation randomness can be measured (as CAGE 4 decision 10). **10 evaluation seeds (0-9) x 100 episodes** per method: CybORG seed s, and Python `random`, NumPy and torch seeded with s just before the first episode (the policies sample their actions). Retraining (`train_subpolicies.py`, `train_master.py`, `train_marl.py`) is NOT ATTEMPTED in this stage. | STANDARD requirement 5, as far as released policies allow | 2026-11-25 |
| 9 | Verdict | A printed value stands for the interval of half a unit of its last digit. **MATCH**: that interval meets our 95% CI of the mean (t over the 10 seed values, each a 100-episode evaluation like one table entry). **CLOSE**: for rewards, our mean within the published episode std (as CAGE 4); for Table 3's other metrics, which have no published std, the interval meets our 95% **prediction interval for one 100-episode evaluation** (mean +- t sd sqrt(1 + 1/10)), i.e. the published single evaluation is within the spread of ours. Else NO MATCH. "Reproduced" needs every attempted primary target MATCH. | fixed before results | 2026-11-25 |
| 10 | Primary targets | Primary: Table 2's Default Red mean for the three released methods, and Table 3's Clean Hosts, Non-Escalated Hosts, Mean Time to Recover, Useful and Wasted Recoveries, Recovery Precision and Red Impact Count for them (24). Secondary: Recovery Error (= 1 - precision) and Table 3's reward (repeats Table 2). The published episode stds are reported beside ours, not as targets. Training claims (Section 4.2 gains, Section 5.1 speed-up) are NOT ATTEMPTED (they need retraining). | fixed before results | 2026-11-25 |
| 11 | Inconsistencies found in the paper (before any run) | H-MARL Collective against Default Red is -237.61 in Table 2 but -255.56 in Table 3; MARL Decentralized is -179.8 in Table 2 and -180 in Table 3 (rounding). Collective is not attempted; both are reported. | honest record | 2026-11-25 |
| 12 | Machine and workers | **GPU PC 2** (CPU only for this simulator), 4 worker processes, one thread each (the CAGE 4 run ran out of memory at 10). Changed on 2026-11-25 at the user's request, before any result: a run started on the development PC was stopped after 0 finished seeds and nothing from it was kept (its `check` and `verify` passed there). The development PC reruns kept episodes as the second machine (`recheck`). | lesson from CAGE 4; the user's choice | 2026-11-25 |
| 13 | Earlier attempt | A teammate's kit (`reproduction_dump/`, 79ff1e72) could not run the evaluation (no Python 3.10, no Ray) and reports no measured value. Nothing from it is used except as a pointer to the repository. | disclosure | 2026-11-25 |
