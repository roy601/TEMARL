TEMARL — What We Did, What We Found, and What It Means

Transformer-Enhanced Multi-Agent Reinforcement Learning for Adaptive Honeypot Deception. This report explains every decision, every experiment, every result table, and — honestly — why the architecture claim in the title did not hold, and what the thesis can claim instead.

The one-paragraph summary

We built a honeypot-deception system where four defender agents place decoys against an attacker whose behaviour comes from real attack data. The system works: it contains the attacker 60.4% of the time versus 54.8% for a defender with no attacker model, and 36.4% for no deception at all. But the specific claim in the title — that a Transformer reads attacker behaviour better than older sequence models — is not true here. We proved instead something more precise and still positive: the Transformer performs statistically the same as a GRU while using 44% of the parameters.

1. What the thesis set out to prove

A honeypot is a fake computer used to trap attackers. If the defender can guess what the attacker will do next, it can put the right kind of fake bait in the right place. The thesis proposed that a Transformer — the model behind ChatGPT — would guess better than older sequence models such as a GRU or LSTM, because attacks are sequences of steps.

Two different claims live inside that sentence

ClaimWhat it needsStatus
A — System claim. Building this system (Transformer + multi-agent RL + MITRE-grounded deception) works. Show it beats sensible defenders that have no attacker model. SUPPORTED
B — Architecture claim. The Transformer beats GRU/LSTM at this job. A fair head-to-head with statistics. NOT SUPPORTED

Most of this report is about how we tested B as hard and as fairly as possible, and why the honest answer is "no" — while A survives and is what the thesis should be built on.

3. The dataset — what it is and everything we did to it

3.1 Which dataset, and why

CAM-LDS is a published set of real, scripted attack campaigns run on a test network (the "AttackBed" testbed). Each campaign is a sequence of MITRE ATT&CK techniques — the standard catalogue of what attackers actually do (for example T1059 = running malicious commands).

We also examined COMISET, a much larger honeypot log dataset, but used it only for encoder pre-training experiments — never for the main results.

PropertyValueMeaning in plain words
Playbooks (runs)3636 recorded attack runs
Labelled technique steps1,3471,347 individual attacker actions
Distinct campaigns (scenarios)77 different attack "storylines"
Parent techniques8282 kinds of attacker action
Tactics1313 attacker goals
Kish effective sample size3.09 The 36 runs are really only ~3 independent campaigns. This is a very small dataset.

3.2 We rebuilt the dataset from source, and found five real bugs

The original version was reconstructed by hand from the paper's text. We replaced it by parsing the 36 published playbook files directly. Then a second, independently written parser was used to check the first. It found bugs the first one had.

RoundDefectDamage
1Two files use singular tactic: instead of tactics:An entire campaign silently dropped
1.j2 and .j2.yml are the same playbookOne campaign counted twice
2Block-order bug — when tactics: appeared before techniques:, nothing was recordedLost T1190, T1059.004, T1095
2Inline # comment bug (×2 variants)Lost 1× T1222.002 and 4× T1219
Net effect of round 28 lost actions recovered: 1,339 → 1,347

Separately, source verification found 6 technique types the hand reconstruction had missed entirely (T1069, T1218, T1518, T1572, T1614, T1615) — 6.20% of all attacker actions were being silently thrown away as "unknown". We extended the vocabulary from 78 to 84 techniques, append-only so old IDs stayed valid.

Three claims we had to withdraw about our own data

  • "82 techniques and 13 tactics match the published paper exactly." FALSE. The apparent perfect match was an accident of the bugs cancelling out. It is 82 against the paper's 81.
  • "The hand reconstruction invented technique T1095." FALSE. T1095 is genuinely there in scenario_7.j2 line 95 — the block-order bug was hiding it. The reconstruction's precision is 100%, not 98.7%.
  • "COMISET is 1156× bigger than CAM-LDS." MISLEADING. 98.5% of its steps are the same action repeated. After collapsing repeats it has 23,754 usable transitions — the real advantage is about 18×, not 1156×.

3.3 Yes — we clustered the dataset, and that clustering caused the failure

You asked specifically about clustering. We did cluster, in one place, and it turned out to be the single most damaging decision in the project.

The 7 campaigns were grouped into 3 "intent classes" by a function called consolidate_intent_classes(). The grouping rule was: campaigns that need the same best decoy are the same intent. The three clusters were even named after their own answers: decoy_persona, decoy_file, decoy_credential.

Why this was fatal for the thesis question

If you group attacks by "which answer is correct", then knowing the group is the answer. The defender never has to read the sequence — it only has to work out which of 3 boxes it is in.

We measured exactly how bad this was. Within each cluster, the best decoy was the same for 84 out of 84 techniques in two clusters, and 83 of 84 in the third. So:

What the defender knowsExpected payoffGain
Nothing (best single fixed decoy)0.3584—
The cluster label (3-way guess)0.7426+0.3842
Perfect prediction of the next technique0.7427+0.0001

Perfect sequence prediction was worth +0.0001 — that is 0.0% of what the cluster label was worth. The task was 3-way classification wearing a sequence costume. No Transformer, GRU or LSTM could possibly have distinguished itself on it.

3.4 The estimator bug that destroyed 87% of the sequence structure

The environment turns each campaign into a transition table: "after technique A, how likely is technique B?" The code that built this table had one damaging line:

T[:, j] += 1.2  — added identically to every row.

A number added identically to every row carries zero information about what follows what — by definition. Worse, it added 7.2–8.4 units of mass per row against only 4.0 units from the real observed data, so the noise outweighed the signal roughly 2:1. Between 55% and 74% of rows became literally identical to one another.

MeasureBeforeAfter removing the line
Sequence information kept, per campaign0.627 bits1.935 bits
(the raw data actually contains)4.83 bits — 85.4% predictable
Value of perfect sequence prediction (payoff)+0.0002+0.1776
Value of perfect sequence prediction (success rate)+0.0005+0.0800
Different best decoys per campaign1.334.33

Proof this was a one-line change, not tuning. Setting the constant back to 1.2 reproduces the old campaign profiles bit-for-bit (largest difference 0.000000). We also tested two other repairs we expected to help — better smoothing, and using all 7 campaigns instead of 3 — and rejected both, because measurement showed they made things worse (−0.0588 and −0.0305). Only the change justified by the mathematics was kept.

4.2 Repairing the environment broke the measurement, and we had to fix that too

Removing the damaging constant made episodes 3× longer (5.45 → 18–22 steps). That caused the success rate to saturate at 0.79–0.98 — every policy looked good, so nothing could be compared. This is exactly the failure the project's own environment gate was written to catch (version 1 of this project was rejected for it).

So we re-calibrated two constants against four criteria fixed in advance, using only non-learning baseline policies (so no architecture could influence the choice). Of 20 combinations tested, exactly one passed all four:

Fairness rules we enforced on every model

  • Capacity matched where compared (entity encoders within 0.7%).
  • Identical padding handling — the single most common way to fake a Transformer win is to let padding leak into the RNN.
  • Equal tuning budget — 16 random-search trials each, selected on validation, scored on a held-out test set.
  • Identical data, identical seeds, identical evaluation — every comparison is paired on the same random seeds.

6. How we benchmarked — the measuring instrument

This is the part that turned out to matter most, and it is a genuine contribution of the thesis.

6.1 The reference ladder

A number like "success rate 0.45" means nothing on its own. So we built a ladder of reference policies, each given more information than the last:

RungWhat it knows
nullNothing — places no decoys. The floor.
randomPicks decoys at random.
best_fixedAlways plays the single best decoy. No attacker model at all — this is the bar a learned model must clear.
profilePerfectly knows which of the 3 campaign clusters it faces.
transitionPerfectly predicts the next technique. This is the ceiling for any history encoder — it is the encoder's whole job, done perfectly and for free.
clairvoyantSees the actual next technique. Unattainable; bounds everything above.

The key quantity: "sequence value"

sequence value = (perfect next-technique model) − (perfect cluster label)

If this is zero, no sequence model can possibly distinguish itself, however good it is. This single number is what revealed that the original experiment was unable to answer its own question.

6.2 The validity gate

Before comparing two models, we now check that each one actually learned the task — it must beat best_fixed significantly. Without this check, a "no difference" result is meaningless, because it cannot tell apart "both are good" from "neither learned anything".

#ReasonEvidence
1The dataset is tiny. 7 campaigns, effective sample size 3.09. Transformers need large data.Kish n = 3.09

Important nuance for your defence: reasons 1, 2 and 5 are properties of the problem, not faults in the Transformer. The model is not broken. The task simply does not have enough sequential structure, or enough remaining headroom, for attention to demonstrate an advantage.

Claim 3 — Methodological findings (publishable in their own right)

  • A pre-registered environment gate can pass while the environment is useless for the actual hypothesis. Ours did: it asked "is attacker information worth anything?" (yes, 0.2698) and never asked "is sequence information worth anything beyond a class label?" (+0.0001).
  • Architecture comparisons need a baseline ladder and a validity gate. Without them, v4 produced 8 null results from 5 models that had never learned.
  • Small-sample effects in this domain do not survive. Four for four.

Claim 4 — Data contributions

  • A source-verified CAM-LDS grounding with five parser defects found and fixed, verified by an independently written second parser.
  • A quantified estimator defect: a column-constant in a transition matrix that destroyed 87% of the corpus's sequential information.
  • Vocabulary extension recovering 6.20% of attacker actions that were being discarded as unknown.

11. Honest limitations (state these before an examiner finds them)

  1. Training is behaviour cloning, not reinforcement learning. Under PPO no model beat the memoryless baseline at any budget tried (240 episodes → 0.510, 1,200 → 0.523, baseline 0.5475). We report encoder quality under matched supervision, not a full MARL result.
  2. Why PPO fails is unresolved. Two hypotheses were tested and both were false: reward/metric conflict (correlation was +0.983, so no conflict), and a log-probability averaging bug (fixing it made results worse).
  3. Sample size n=10 detects only very large effects; the confidence intervals, not the p-values, carry the argument.
  4. One environment, one scripted attacker. A learning attacker could change everything.
  5. The repaired environment is calibrated, chosen from 20 candidates against pre-declared criteria — a different calibration might differ.
  6. The LSTM was given the GRU's tuned settings, not its own search.

One number that must never be quoted

The v5 data, re-tested with a one-sided test, gives p = 0.0431, which looks significant. It is not a valid result. v5 was registered as a two-sided, multiplicity-corrected test and stands at p = 0.690. Switching test type after seeing the data is exactly the manipulation that invalidates a thesis. It is recorded here so nobody quotes it by accident.
